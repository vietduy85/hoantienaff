# Sửa logic clone policy — bản clone độc lập hoàn toàn

## 1. Nguyên nhân chính xác

Sau khi **clone** một chính sách hệ thống rồi **chỉnh sửa và lưu bản clone**, một
số thông tin vẫn mang giá trị của **chính sách nguồn**:

### 1.1 Ghi chú blueprint bị chép nguyên văn kèm TÊN TEMPLATE NGUỒN
`PolicyCloneService::createSystemPolicyFromEditor()` (luồng clone) gán:

```php
'note' => $blueprint->note,
```

Ghi chú của blueprint hệ thống do hệ thống **sinh tự động** theo tên template:
- `Blueprint version N của template "<tên>".` — sinh bởi `createBlueprint()`;
- `Chính sách hệ thống <tên>.` — sinh bởi seeder.

Editor **không có ô nhập ghi chú**, nên ghi chú chép sang vẫn trỏ **tên template
nguồn** → bản clone hiển thị sai tên chính sách.

### 1.2 Trần hoàn tiền tổng (cột legacy cấp policy) bị chép nguyên văn
Cùng hàm gán:

```php
'max_cashback_total_per_period' => $isEdited && array_key_exists('max_cashback_total_per_period', $overrides)
    ? $overrides['max_cashback_total_per_period']
    : $blueprint->max_cashback_total_per_period,   // <-- kế thừa nguồn
```

Nhưng editor `versionConfig()` (`policy-editor.blade.php`) **chỉ gửi**
`effective_from`, `tiers`, `min_total_spend` — **không** gửi trần tổng.
`UpdateSystemPolicyVersionRequest` cũng **không** có trường này. Nghĩa là:

- lúc clone: bản clone kế thừa trần của nguồn;
- khi "Lưu lại": `updateSystemVersion()` chỉ cập nhật trần nếu khoá **có mặt**
  trong payload — mà payload không có → trần cũ **giữ nguyên vĩnh viễn**.

Điều này **cố ý** ở thiết kế cũ (backward-compat theo `docs/CREDIT_CARD_SYSTEM_POLICY_ADMIN_REPORT.md`
§21 — trần mỗi kỳ đã chuyển từ cấp policy xuống cấp bậc), nhưng nó vi phạm yêu cầu
"bản clone độc lập". Bản clone của một template phải có **danh tính mới**, không
được mang giá trị hoặc tên của nguồn.

## 2. Luồng clone/lưu/đã sửa

Chỉ sửa **luồng clone hệ thống** trong `PolicyCloneService::createSystemPolicyFromEditor()`:

### 2.1 Ghi chú — sinh lại theo template ĐÍCH
Thêm `cloneBlueprintNote()` + `isAutoGeneratedNote()`:

- Nếu ghi chú nguồn **rỗng/null** hoặc khớp mẫu sinh tự động (`Blueprint version N
  của template "…".` hoặc `Chính sách hệ thống …`) → sinh lại
  `Blueprint version <version_no> của template "<tên template đích>".`
- Nếu ghi chú do **admin tự nhập** (không khớp mẫu tự động) → **giữ nguyên**
  (không phải dữ liệu sao chép tự động).

### 2.2 Trần hoàn tiền tổng — không kế thừa
Bản clone đặt `max_cashback_total_per_period = null` **trừ khi** editor gửi tường
minh khoá này (khi đó dùng đúng giá trị editor gửi). **Không tự cộng** trần các
bậc thành trần tổng (trần mỗi kỳ thực tế nằm ở từng bậc).

### 2.3 Giữ nguyên các hành vi khác
- `version_no`, `status`, `effective_from/to`, `min_total_spend`, `rounding_mode`,
  tiers/rules/transaction_caps: sao chép như cũ.
- `is_locked` luôn `false`; `default_version_id` remap sang blueprint clone.
- `updateSystemVersion()` (Lưu lại) **đã** hỗ trợ persist trần tổng nếu payload có
  khoá — không cần sửa.
- **Không** thêm ô trần tổng vào editor/request (giữ §21: editor không quản trần
  cấp policy). **Không** sửa logic tính cashback dùng chung. **Không** sửa
  `attachTemplateToCard` (clone template → thẻ) — luồng này đã sinh ghi chú riêng
  `Sao chép từ template "…"`.

  `editing_tier_in_clone_does_not_affect_source`, `restructuring_clone_does_not_affect_source`)
  đều PASS.
- Fix chỉ tác động **bản ghi mới** trong bản clone; không có đường ghi ngược về nguồn,
  không cascade sang template/thẻ khác.

## 6. Xác nhận không commit / push / deploy

- **Không** commit, **không** push, **không** deploy.
- **Không** sửa `.env`, **không** chạy `migrate:fresh`/`db:wipe`/rollback rộng.
- Task này **không cần migration** (chỉ đổi luồng clone tại thời điểm tạo bản ghi;
  các bản clone cũ đã tạo trước đây không bị đụng — nằm ngoài phạm vi "sửa luồng clone/lưu/hiển thị").
